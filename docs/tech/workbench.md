# 两种形态

yoyo 是一个常驻进程，两个入口：

| 形态   | 什么时候用                                     | 在哪                                                     |
| ------ | ---------------------------------------------- | -------------------------------------------------------- |
| 桌宠   | 大部分时间：碎碎念、提醒、听你说、右键聊一句   | 桌面上的 dsh-pet                                         |
| 工作台 | 真要干活、翻历史、看它做过什么、改配置的时候   | yoyo.app 的窗口；不用 app 时是浏览器里的同一页           |

两边是同一份东西：同一个常驻进程、同一份对话上下文和记忆、同一套日程。桌宠右键聊的、语音说的、工作台里打的，都进主聊天，工作台里按来源标出来。工作台就是[管理页](web.md)长大以后的样子，地址、令牌、安全边界都不变。

# 已经有的

布局照着常见的聊天工作台：最左边一列图标，中间是聊天列表，右边是当前的视图。[^page]

* **对话**：主聊天。消息按时间排，隔了一刻钟插一行时间；碎碎念是一行灰字，摘要可以展开；新加的日程排在对话里成一张卡片。桌宠右键对话和语音说的标上来源。底下的输入框打字就和 yoyo 聊（`POST /api/chat`），Enter 发送，Shift+Enter 换行，输入法选字的回车不算。开着时每 4 秒看一眼有没有新的。右上角能搜当前对话、跳到日程。
* **聊天列表**：主聊天一项；子聊天还没有，先占着位置。底下是状态（桌宠、模型、右键对话、记忆、在忙什么、下一句碎碎念）和「说一句」「听一句」。
* **心迹**：画像、记得的事、规矩。**日程**：加、删。**轨迹**：做过的事，按天分，类型换成中文。**联系人**、**设置**：和原来的管理页一样。

工作台里聊的一句走编排器的 `talk`：和右键对话同一个 agent（记忆、工具、MCP、搜索），回上来以后把问答记进日志，来源是 `workbench`，再记一笔 `chat-workbench`。不念、不冒泡，免得工作时桌宠插嘴；算作说过话，碎碎念照样让路。没回上来就不记，页面上把那句放回输入框。[^orchestrator] [^api]

# 提案：子聊天

主聊天是和 yoyo 的日常；要专门干一件事时开一个子聊天，不把主聊天搅乱。

* **是什么**：一个子聊天是 ctx 的一个独立会话（`sessionFor('chat:<id>')`），有标题、建的时间、归档时间。存在 `yoyo.db` 新的 `chats` 表里，对话照旧在上下文存储里。
* **看得到什么**：画像和记得的事（记忆来源照常给），看不到主聊天的对话。要用主聊天里的东西，就在开的时候带一段：开子聊天时可以选「带上最近的对话」，把最近几轮压成一段摘要放进子聊天的第一条。
* **回到主聊天**：子聊天归档时，yoyo 写一句结论记进主聊天（事件 `chat-done`，带子聊天的 id 和标题），主聊天里显示成一张卡片，点开回到子聊天。
* **桌宠**：右键对话只进主聊天。子聊天只在工作台里。

接口：`GET /api/chats`、`POST /api/chats { title }`、`GET /api/chats/:id/context`、`POST /api/chats/:id/messages { text }`、`PATCH /api/chats/:id { archived }`。`/api/chat` 和 `/api/context` 照旧指主聊天。

# 提案：子 agent 任务

主聊天里说「帮我把这周的周报整理出来」，yoyo 开一个子聊天在后台做，做完了告诉你。

* **怎么开**：回复的 agent 多一个工具 `delegate({ title, goal })`，只在 `llm.tools` 打开时给。它建一个子聊天，把 `goal` 当第一句交给任务 agent，马上回一句「开了个子聊天去做」，不等做完。工作台的聊天列表里也能手动开任务。
* **怎么跑**：编排器的 `submit` 交到子聊天的会话，在后台跑，不占舞台、不碰桌宠，碎碎念照常。任务 agent 和回复的 agent 用同样的工具和 MCP（沙箱照旧），另外有 `deliver`（见交付物）。同时最多跑 2 个，多的排队。
* **状态**：排队、在跑、做完、失败、取消，记在 `chats` 表上（`task_state`、`started_at`、`finished_at`、`error`）。每一步（调了什么工具、写了什么）进子聊天的日志，工作台里能看着它做。能取消：中止这一轮。常驻进程重启时 `recover()`，没做完的标成失败，能重试。
* **做完了**：主聊天里记一张任务卡片（标题、结果一句话、交付物几个）；桌宠冒泡一句「周报整理好了」，按 `tasks.notify` 决定念不念（缺省只冒泡）。
* **记一笔**：`task-start`、`task-done`、`task-fail`、`task-cancel`，轨迹里看得到。

# 提案：交付物

任务产出的东西：一段整理好的文字、一个 Markdown、一张图、一个表格。

* **存在哪**：`~/.yoyo/artifacts/<子聊天 id>/<文件名>`，表 `artifacts`（id、子聊天、文件名、类型、大小、时间）。
* **怎么来**：任务 agent 的工具 `deliver({ name, content })`，只能写进自己子聊天的那个目录，文件名去掉路径；单个最大 5 MB。不给通用的写文件工具。
* **怎么看**：顶栏「交付物」打开右侧面板，列出这个子聊天（主聊天里是全部）的交付物；文本和 Markdown 直接预览，图片显示，别的下载。yoyo.app 里多一个「在访达里显示」。
* **接口**：`GET /api/artifacts?chat=`、`GET /api/artifacts/:id`（原文，带对的 `content-type` 和 `content-disposition`）、`DELETE /api/artifacts/:id`。

# 分期

| 期 | 做什么                                                                       | 要先有                       |
| -- | ---------------------------------------------------------------------------- | ---------------------------- |
| W0 | 工作台外壳、主聊天能打字、心迹/日程/轨迹/设置换样式（已做）                  | 管理页                       |
| W1 | 子聊天：手动开、聊、归档，结论回主聊天                                       | `chats` 表，按会话读写上下文 |
| W2 | 子 agent 任务：`delegate`、后台跑、状态、取消、做完冒泡                      | W1；编排器按会话并发         |
| W3 | 交付物：`deliver`、面板、预览                                                | W2                           |
| W4 | 工作台里流式显示回复；桌宠右键里看任务进度                                   | ctx 的流式事件               |

# 还没定

* 子聊天要不要也能从桌宠右键开（例如「新开一个子聊天」）。
* 任务做完念不念出来；缺省先只冒泡。
* 交付物要不要同步到别的地方（例如 iCloud 文件夹）。
* 主聊天变长以后，工作台要不要分页往前翻，而不是只看最近 200 条。
