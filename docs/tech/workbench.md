# 两种形态

yoyo 是一个常驻进程，两个入口：

| 形态   | 什么时候用                                     | 在哪                                                     |
| ------ | ---------------------------------------------- | -------------------------------------------------------- |
| 桌宠   | 大部分时间：碎碎念、提醒、听你说、右键聊一句   | 桌面上的 dsh-pet                                         |
| 工作台 | 真要干活、翻历史、看它做过什么、改配置的时候   | yoyo.app 的窗口；不用 app 时是浏览器里的同一页           |

两边是同一份东西：同一个常驻进程、同一份对话上下文和记忆、同一套日程。桌宠右键聊的、语音说的、工作台里打的，都进主聊天，工作台里按来源标出来。工作台就是[管理页](web.md)长大以后的样子，地址、令牌、安全边界都不变。

# 已经有的

外观是 yoyo 自己的：她的头像、取她头发的蓝紫做主色，浅色深色各一套。设计稿在 Artifact「yoyo 工作台」里（对话、子任务详情、记忆三屏）。布局是一列侧栏加当前视图：侧栏从上到下是 yoyo 的头像和此刻在做什么、导航、子任务和进度、运行状态，窄窗口收成一列图标。[^page]

* **对话**：主聊天。yoyo 的话在淡蓝气泡里带头像，主人的话是实心气泡；隔了一刻钟插一行时间；碎碎念是居中一行，摘要可以展开；记下的闹钟、派出去和做完的子任务是一行小卡片，子任务的带着进度，点开看详情。桌宠右键对话和语音说的标上来源。底下的输入框打字就和 yoyo 聊（`POST /api/chat`），Enter 发送，Shift+Enter 换行，输入法选字的回车不算。开着时每 4 秒看一眼有没有新的。右上角能搜当前对话、跳到日程。
* **待批准**：侧栏导航里「对话」下面，旁边的数字是等批准的件数；状态区也多一行「N 件事等你批准」。开关写成 `ask` 的工具（读写文件、跑命令）被 yoyo 调用时，不当场做，在这里等你点头，规则见[先问](files.md#先问)。页上先列等批准的，每条一张卡片：工具、一句摘要（「写 notes/周报.md（新建，12 行）」「跑命令：python plot.py」）、谁要的（yoyo 或哪个子任务）、时间；「看完整参数」展开写的内容、改的原文和新文、整条命令（展开的状态 4 秒一刷新也不丢，另取 `GET /api/approvals/:id`）；「批准」「拒绝」两个按钮。下面是最近批过、拒绝、过期的，展开能看参数和做完的结果。主聊天里每条请求一张「要你批准」的卡片（状态跟着变），结论写回来是一张卡片；子任务在等批准时，详情最上面是它要批的事。接口见[管理页](web.md#接口)。
* **侧栏的子任务**：状态和 todo 进度，在做的带进度条。底下是状态（桌宠、模型、右键对话、记忆、在忙什么、下一句碎碎念）和「说一句」「听一句」。
* **记忆**：画像能直接改；记得的事按话题筛、带召回次数；规矩标出生效还是待确认。**日程**：加、删。**轨迹**：做过的事，按天分，类型换成中文。**联系人**、**设置**：和原来的管理页一样。

工作台里聊的一句走编排器的 `talk`：和右键对话同一个 agent（记忆、工具、MCP、搜索），回上来以后把问答记进日志，来源是 `workbench`，再记一笔 `chat-workbench`。不念、不冒泡，免得工作时桌宠插嘴；算作说过话，碎碎念照样让路。没回上来就不记，页面上把那句放回输入框。[^orchestrator] [^api]

# 子任务（已做）

原来提案的「子聊天」不做了：主人大多数时候只和主线程说话，要专门干的事由主线程派成子任务，在后台由子 agent 做。子任务有结构化的目标、验收标准和 todo，子 agent 边做边更新 todo，做完把结果交回主线程。怎么存、怎么跑、怎么回到主线程见[子任务](tasks.md)。

工作台里，聊天列表的「子任务」一栏列着它们（状态、todo 进度），点开是详情；主聊天里派出去和做完的各是一张卡片。

子 agent 做到一半问主人时（`task_ask`，规则见[中途问主人](tasks.md#中途问主人)），子任务显示「等回答」：侧栏里在做的和等回答的排在最前，主聊天里多一张「想问主人」的卡片，详情最上面是问题和一个回答框（`POST /api/tasks/:id/answer`），答了子任务排队接着做。回答框里写了一半的话，4 秒一刷新不会丢。

# 交付物（已做）

子任务产出的文件：整理好的 Markdown、表格、图。子 agent 用 `task_deliver` 交，存在 `~/.yoyo/artifacts/<子任务编号>/`，表 `artifacts` 记一条；规则见[子任务](tasks.md#交付物)。

* **怎么看**：子任务详情里结果下面一块「交付物」，一行一个：文件名、大小、时间。文本（Markdown、CSV、JSON）展开是原文，图片展开显示；HTML、SVG 和别的只给下载。浏览器里能下载；yoyo.app 的窗口里下载不了，换成「在访达里显示」。都能删。
* **接口**：`GET /api/artifacts?task=`、`GET /api/artifacts/:id`（原文，带对的 `content-type` 和 `content-disposition`，关在沙箱里）、`DELETE /api/artifacts/:id`、`POST /api/artifacts/:id/reveal`，见[管理页](web.md#接口)。
* **还没做**：顶栏列出全部交付物的一页；Markdown 排版好再显示（现在是原文）。

# 分期

| 期 | 做什么                                                                       | 状态 |
| -- | ---------------------------------------------------------------------------- | ---- |
| W0 | 工作台外壳、主聊天能打字、心迹/日程/轨迹/设置换样式                          | 已做 |
| W1 | 子任务：主线程派、子 agent 拆 todo 边做边标、验收后交回主线程、工作台看进度  | 已做 |
| W2 | 交付物：`task_deliver`、子任务详情里列出、预览、下载或在访达里显示、删       | 已做 |
| W3 | 子任务并行（已做）；子任务中途问主人（已做）；工作台里流式显示回复           | 部分 |
| W4 | 先问：读写文件、跑命令的开关写成 `ask`，工作台的「待批准」里批准或拒绝       | 已做 |

# 还没定

* 交付物要不要同步到别的地方（例如 iCloud 文件夹）。
* 主聊天变长以后，工作台要不要分页往前翻，而不是只看最近 200 条。
