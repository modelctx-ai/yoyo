# 要做的

1. 按[安装与运行](getting-started.md#安装)把 ctx 克隆到 yoyo 旁边，用 `pnpm install` 装依赖。
2. 启动一次常驻进程（`pnpm start`）。旧数据会自动迁移，桌宠里存的旧模型密钥也会被换掉。

# 变化

| 变化     | 说明                                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------------------- |
| 命令     | `npm` 换成 `pnpm`。`node bin/yoyo.js` 和 `node src/main.js` 照旧能用                                                       |
| 配置     | 旧 `config.json` 原样可用，新加的键都有缺省值，写错的值按缺省值算。`listen` 不写仍然不听                                   |
| 对话记忆 | 第一次启动时自动迁到新的存储，旧数据留着备份。迁移失败就原样回滚，下次启动再试                                             |
| 旧 JSON  | 数据目录里的旧版 JSON 文件导进 `yoyo.db` 一次，再改名成 `*.migrated`                                                       |
| 右键对话 | 桌宠拿到的是每次启动新生成的本机令牌，不再是真的 `llm.apiKey`                                                              |
| 粘贴板   | 最近一条现在真的交给模型了。以前的说明一直这么写，旧代码收集了却没交给模型。不想要就把 `clipboard.enabled` 设成 `false` |
| 语音缓存 | 文件名不变，不用重新合成                                                                                                   |

# 从上一版升级（ctx 0.2）

yoyo 改用 ctx 0.2。先更新 ctx 并重新构建，再装一次依赖：

```sh
git -C ../ctx pull
pnpm -C ../ctx install && pnpm -C ../ctx build
pnpm install
```

对话记忆的存储格式随 ctx 0.2 有一处改名。第一次打开数据时（常驻进程或任何读写对话记忆的命令）自动改好，以前的记忆原样都在，不用做什么。改失败就原样回滚，下次再试。改过以后，旧版 yoyo 读不了这份对话记忆。

# 从上一版升级（ctx 0.3）

yoyo 改用 ctx 0.3。**先停掉常驻进程**，因为常驻进程和命令行共用 `~/.yoyo/yoyo.db`，库结构升到新版以后旧版读不了，所以别让两个版本同时开着。更新 ctx 并重新构建，再装一次依赖：

```sh
git -C ../ctx pull
pnpm -C ../ctx install && pnpm -C ../ctx build
pnpm install
```

第一次打开数据时（常驻进程或任何读写对话记忆的命令）库结构自动升级，以前的对话记忆原样都在，不用做什么。

升级前压缩出的旧摘要，有可能盖住了桌宠对话后来补进来的几条记录。常驻进程启动时会检查一次：有，而且配了模型，就重新压缩一次，日志里有一行说明；没配模型就记一条警告，下次带着模型启动时再做。命令行不做这一步。
